# Bose SoundTouch Reborn – Home Assistant Custom Integration

**Community-developed, unofficial integration** for Bose SoundTouch speakers running ST-Reborn firmware. Not affiliated with or endorsed by Bose or the ST-Reborn maintainers.

## Status

- Integration version: **0.1.1 (experimental)**
- Tested on a dedicated HAOS-X1 Home Assistant 2026.11.2 installation with ST-Reborn v1.5.3 on SoundTouch 10, 20 and 30.
- **Not yet validated on Home Assistant 2026.10.4 production**, or across firmware upgrades.
- A few temporary local API timeouts were observed during testing; robustness for intermittent connectivity still requires evaluation.

## Installation

Copy `custom_components/str_reborn/` into the target HA config directory, restart Home Assistant, then add **SoundTouch Reborn** via Settings → Devices & Services → Add Integration. Supply each speaker's local IP address. The flow probes ports 17008 and 8888 if no port is specified.

For later HACS installation, add this repository as a **custom integration** repository (if supported by your HACS version). This source tree uses the standard `custom_components/<domain>` layout.

## Features

- Media player: power, volume, play/pause/stop, radio preset playback, supported URL streams.
- Preset buttons 1–12 (second preset bank when exposed by the device).
- Sensors: station / active saved preset, stream track, ST-Reborn version.
- Button to refresh status.
- Service `str_reborn.announce` with native **speaker dropdown** (config-entry selector), text or HTTP(S) audio URL, language and volume.
- Local polling of the speaker API; Home Assistant does not require the original Bose cloud.

### Example: announcement

In Home Assistant go to Developer Tools → Actions and select `str_reborn.announce`. Choose a speaker in the `Lautsprecher` field, enter text or a reachable audio URL and optionally volume.

```yaml
action: str_reborn.announce
data:
  entry_id: REPLACE_WITH_YOUR_LOCAL_HA_ENTRY_ID
  text: "Testansage über SoundTouch Reborn"
  language: de
  volume: 35
```

The `entry_id` is specific to the individual Home Assistant installation and **must never be copied from X1 to production**.

## Important limitations

- Announcements may not resume every source (for example AUX/Bluetooth). Test in your environment.
- The text announcement implementation may use an external Google Translate TTS endpoint, depending on firmware. Use an HTTP(S)-reachable prerecorded file (for example generated by Edge TTS) if cloud transmission of announcement text is undesirable.
- This integration does **not install ST-Reborn firmware updates**. It only reads the installed version.
- The local speaker API has no authentication; restrict reachability to a trusted LAN/VLAN.
- Preset/station parsing is based on tested ST-Reborn XML status and encoded preset stream descriptors.
- The included graphical icon is user-provided/generated artwork and includes third-party marks; do not assume redistribution rights beyond your own permitted use.

## Update workflow

1. Develop and test changes on HAOS-X1.
2. Review changes and tag a tested version in Git.
3. Back up Home Assistant production before deployments.
4. Deploy only the tested `custom_components/str_reborn` directory; do not copy X1 `.storage` or config entries.
5. Restart Home Assistant, test one speaker, then the remaining speakers and announcement automations. Roll back by restoring the prior integration files if needed.
